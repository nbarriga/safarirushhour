# Safari Rush Hour solver: version used to compute search metrics

> **This branch is a fixed snapshot.** It is commit `70e228a` of the solver (November 2022), plus a
> metrics mode that records the A\* search, solution-path and structural metrics of every board. It
> was used to compute the metrics of a study on puzzle difficulty, and it is kept so that those
> numbers can be reproduced exactly. The current version of the solver, with more algorithms and
> heuristics, a test suite and a corrected `obstacles2`, is on the `master` branch. This branch is
> not meant to be merged into it.

The sections on the game, the input format and `verify` are adapted from the README of `master`
and checked against the code of this version.

## About Safari Rush Hour

Safari Rush Hour is a variant of the Rush Hour sliding-block puzzle by ThinkFun, played on a
**7×7 grid**.

### Pieces

| Letters | Piece | Moves |
|---|---|---|
| `x` | The rover, 2×2 | Up, down, left and right |
| `u`, `v` | 2×2 animals | Up, down, left and right |
| `o`, `q`, `s`, `p`, `r` | 3×1 animals | Only along their orientation (left/right if horizontal, up/down if vertical) |
| `a`, `f`, `d`, `g`, `j`, `b`, `h`, `i`, `k`, `c`, `e` | 2×1 animals | Only along their orientation |

A move slides one piece one or more cells in one direction, without rotating it or jumping over
other pieces.

### Board and exit

Rows and columns are numbered 0 to 6. The exit is on the right edge, at rows 2 and 3. The puzzle
is solved when the rover leaves the board through it (its upper-left corner reaches row 2,
column 7).

```text
       0  1  2  3  4  5  6
Row 0 [.  .  .  .  .  .  .]
Row 1 [.  .  .  .  .  .  .]
Row 2 [.  .  .  .  .  .  .] ===> exit
Row 3 [.  .  .  .  .  .  .] ===>
Row 4 [.  .  .  .  .  .  .]
Row 5 [.  .  .  .  .  .  .]
Row 6 [.  .  .  .  .  .  .]
```

## Building

```
make metrics          # SafariMetrics: metrics driver, needs only a C++17 compiler
make safari verify    # solver and solution checker, need Boost (libboost-program-options-dev)
make clean
```

## Board files

Each board starts with a line `P <name>`, followed by 7 lines of 7 characters: `.` is an empty
cell, `x` the rover, and the other letters the animals. A file can hold any number of boards.

```text
P J1
.......
.rrrf..
hh..fq.
o.xx.q.
o.xx.q.
ob..ee.
.bppp..
```

| File | Boards |
|---|---|
| `Jpuzzles`, `Bpuzzles`, `Ipuzzles`, `Apuzzles`, `Epuzzles` | 10 boards each: J1–J10, B1–B10, I11–I20, A21–A30, E31–E40 |
| `allPuzzles` | 42 boards: J1–J10, B1–B10, I11–I20, A21–A30, E31 and E40 |
| `allSolutions`, `ASolutions`, `BSolutions`, `ISolutions`, `ESolutions` | Reference solutions (`solution` lines, see below) |
| `J1`, `J2`, `J3`, `B1`, `I11`, `A21`, `E31`, `E40` | Single boards |
| `J1J5`, `slowPuzzles`, `NoSolutionPuzzle`, `boards_201709` | Small sets for testing, and a large set of generated boards |

## Metrics mode: `SafariMetrics`

```
./SafariMetrics <board_file> [heuristic] [output.csv]
./SafariMetrics allPuzzles obstacles2 metrics.csv
```

It solves every board of the file with A\* and the given heuristic (`0`, `210`, `obstacles0`,
`obstacles1`, `obstacles2` or `obstacles3`; default `obstacles2`). With an output file it writes
one `;`-separated row per board; without it, it prints a `name: value` report per board. The time
limit is 100,000 s per board, so in practice there is none.

The metrics were computed with `obstacles2`.

### Columns

| Column | Meaning |
|---|---|
| `title` | Board name |
| `solver_time` | A\* wall-clock time, seconds |
| `movements` | Solution length (moves) |
| `br_expanded_nodes` | Expanded nodes |
| `br_real_total_children` | Successors generated by the expanded nodes |
| `br_eff_total_children` | Successors inserted or updated in the open list |
| `br_repeated` | Successors discarded because the state was already in the open or closed list with a g that is not larger |
| `reopen` | Closed nodes put back in the open list (`obstacles2` is not consistent, see below) |
| `open_list`, `closed_list` | Size of the open and closed lists when the goal is found |
| `br_real_avg`, `br_real_min`, `br_real_max` | Successors per expanded node: mean (`br_real_total_children / br_expanded_nodes`), minimum, maximum |
| `br_eff_avg`, `br_eff_min`, `br_eff_max` | Successors inserted or updated in open, per expanded node: mean, minimum, maximum |
| `br_classic` | `br_expanded_nodes ^ (1 / movements)` |
| `br_redundancy` | `br_real_total_children / br_repeated` (0 if nothing was repeated) |
| `sol_br_*` | The same counts along the solution: the successors of every state of the solution path, from the initial state to the one before the goal, with the generator used by A\*. A successor is repeated if it was already generated from an earlier state of the path. Means are divided by `movements`. |
| `F1_pieces` | Pieces other than the rover |
| `F2_cars`, `F3_trucks`, `F4_squares` | 2×1, 3×1 and 2×2 pieces (rover excluded) |
| `F5_occupancy` | Occupied cells / 49 (rover included) |
| `F6_rover_exit_distance` | Columns between the right edge of the rover and the right edge of the board |
| `F7_rover_misalignment` | Rows between the rover and the exit rows |
| `F8_direct_blockers` | Pieces on the exit corridor: rows 2–3, from the right of the rover to the edge |
| `F9_blocked_blockers` | Blockers that cannot slide out of the corridor with the other pieces where they are |
| `F10_horizontal_ratio` | Fraction of horizontal pieces among the 2×1 and 3×1 pieces (−1 if there are none) |

The structural features describe the initial board.

### Notes

- **`obstacles2` is neither consistent nor admissible in this version.** Closed nodes are
  reopened on some boards. On J8, one state of an optimal solution has a heuristic value one
  move larger than the moves that remain, so A\* cannot guarantee shortest solutions. For the boards used in the study, every solution length
  was checked with an independent breadth-first search, and all of them are optimal. The
  heuristic was corrected later on `master` (commit `3ff2908`).
- **Boards solved one after another.** The test that decides whether two states are equal also
  tries swapping the two identical 2×2 animals `u` and `v`. It finds them through a global table
  that is only updated for the letters present in the current board. On a board with `u` and no
  `v`, the solver would therefore use the position of `v` left by an earlier board. For this
  reason `SafariMetrics` resets that table before each board, so every board is solved as in a
  fresh process, whatever was solved before it.

## Solver: `safari`

`safari` reads boards from standard input and prints a `solution` line per board:

```
./safari < J1
./safari -a Astar -h obstacles2 < allPuzzles
```

```
statistics J1 Nodes: 102, average H: 2.65508, cut-off depth (min/average/max): 0/1.90119/4
solution J1 0.33 5  fu1 xu1 el1 qd2 xr5
```

The `solution` line gives the board, the time in seconds, the number of moves and the moves. Each
move is a piece letter, a direction (`u` up, `d` down, `l` left, `r` right) and a number of cells.

| Option | Meaning |
|---|---|
| `-a`, `--algorithm` | `IDAstar` (default), `Astar` or `BFS` |
| `-h`, `--heuristic` | `obstacles0` (default), `0`, `210`, `obstacles1`, `obstacles2`, `obstacles3`, `relaxed1`, `relaxed2` |
| `-t`, `--time` | Time limit per board, seconds (default 60) |
| `-s`, `--size` | Transposition table size, entries (default 10,000,000) |
| `-l`, `--length` | Maximum solution length for IDA\* (default 1000) |
| `-c`, `--cluster` | Reuse solutions between boards of the same cluster |
| `--typett` | Transposition table type: `normal` (array) or `map` |
| `--ccomp` | Enable connected components |

`BFS` is not meant to be used in this version (commit `b92aad8`: "Please do not run BFS/retroBFS
with this version").

### Heuristics of this version

| Heuristic | Value |
|---|---|
| `0` | 0 |
| `210` | 0 at the goal, 1 if the rover is on the exit rows, 2 otherwise |
| `obstacles0` | `210` plus the pieces that block the rover's direct path to the exit |
| `obstacles1`, `obstacles2`, `obstacles3` | Minimum, over the rover's escape routes of up to one, two or three moves (3, 7 and 14 routes), of the moves the route needs plus the pieces on the cells it crosses |
| `relaxed1`, `relaxed2` | Minimum, over every piece (or pair of pieces), of the exact solution length of the board that keeps only the rover and that piece (or pair). Read from `dataOne.bin` and `dataTwo.bin`, which must be in the working directory |

## Checking solutions: `verify`

`verify` replays a solution on its board and prints every intermediate board, then `OK!` if the
solution is legal and reaches the goal, or `BAD!` / `Formatting problem` otherwise. It reads from
standard input: the `P` line, the 7 board lines, an empty line and the `solution` line.

```
(cat J1; echo ""; ./safari < J1 | grep '^solution') | ./verify
```
